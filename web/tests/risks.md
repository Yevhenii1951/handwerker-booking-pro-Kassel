# Test Risks — handwerker-booking-pro-Kassel

Sorted by cost to the user (highest first). Blind-spot areas where a
change can fail silently. Generated by diagnostics prompt 00.

## HIGH — wrong data / data leak / broken core flow

1. `src/app/dashboard/master/schedule/actions.ts:36-37` + `src/lib/slots.ts`
   — `setHours`/`setMinutes` on UTC-midnight Date uses the server's LOCAL
   timezone. On a UTC server (Vercel) every slot is shifted by the
   Berlin-vs-UTC offset (1–2 h). Masters lose edge hours, bookings created at
   wrong real time. All time math must be Berlin-fixed and covered by tests.
2. `src/app/api/auth/callback/route.ts:8,34` — open redirect: unvalidated
   `next` param is concatenated into the redirect URL (`<origin>@evil.com`).
   Post-login phishing. Never redirect to a `next` that is not a local path.
3. `src/app/dashboard/master/bookings/actions.ts:54-58` — status update
   filters only `id`+`master_id`, no current-status guard. A cancelled
   booking can be force-set back to confirmed → phantom appointment and
   misleading customer notification.
4. `src/app/dashboard/master/bookings/actions.ts:36-51` +
   `src/app/(marketing)/handwerker/[id]/booking/actions.ts` — slot
   availability check and booking insert are separate non-atomic queries.
   Concurrent requests can double-book the same slot.
5. `src/lib/proxy.ts` — no auth-guard middleware on `/dashboard/*`. Every
   server component must call `requireUser/requireProfile/requireRole` on
   its own; a forgotten guard silently exposes the page.
6. `src/app/dashboard/master/page.tsx:19-20` + `setup-guard.ts` — admin
   passes `requireRole(["master","admin"])` but fails
   `requireMasterSetup(profile)`, then onboarding redirects admin away →
   infinite redirect loop; admin dashboard unreachable.
7. All `src/app/dashboard/master/*/actions.ts` — admin role accepted by
   `requireRole(["master","admin"])` but every query filters
   `.eq("master_id", profile.id)`, so admin silently gets "not found" and
   cannot manage master data without explanation.

## MEDIUM — degraded UX / latent correctness / missing defense

8. `src/lib/booking.ts:5-9` — `todayBerlin()` relies on `Intl` `en-CA`
   formatting to build `YYYY-MM-DD`; implementation-dependent across
   runtimes/Intl versions. Wrong booking window on non-V8 or updated Intl.
9. `src/lib/slots.ts:31` — `day.getDay()` on UTC Date in a non-UTC server
   (UTC-x) maps weekday to previous day → no slots on window edge days.
10. `src/app/dashboard/master/portfolio/actions.ts:27-28` — file type check
    trusts client-reported MIME; no content inspection. Malicious upload as
    `image/jpeg` possible.
11. `src/lib/geocode.ts:37-42` — Nominatim fetch has no timeout/AbortController
    → server action may hang indefinitely (DoS under outage).
12. `src/app/dashboard/notifications/api/route.ts:4-6` — unauthenticated
    request returns `200 { items: [] }` instead of 401 → silent session
    expiry, missed notifications without error.
13. `src/app/(marketing)/handwerker/[id]/booking/actions.ts:24-90` —
    `getAvailableSlots` runs without auth: visitors can enumerate a master's
    schedule (scheduling data leak / scraping).
14. `src/app/dashboard/customer/page.tsx:26` — master role allowed on
    customer dashboard; role separation blurred.

## LOW — test gaps / hygiene / theoretical

15. All five `src/lib/*.test.ts` files cover happy paths only — no boundary,
    reject or auth tests. No tests for `requireRole`, auth callback, or any
    server action. A refactor of `requireRole` breaks role-based access with
    zero signal.
16. `src/lib/supabase/server.ts:20-22` — cookie `setAll` errors swallowed →
    session refresh fails intermittently without log.
17. `src/app/(auth)/register/register-form.tsx:35` — `role` is client-supplied
    in signup metadata. Safe ONLY if a DB trigger forces `role='customer'`;
    otherwise self-serve admin/master signup.
18. `src/app/dashboard/master/portfolio/actions.ts:47-49` — `getPublicUrl` is
    used unconditionally; if the bucket is public, portfolio paths can be
    enumerated from public master ids.
